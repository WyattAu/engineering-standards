# STANDARDS-INDEX: every concern, its standard, its gate

> **Status: PROPOSED (v0.1.0, 2026-11-09).** Generated by hand, checked by
> `scripts/check-standards-index.py`. Ratification: ADR-0013.

This is the answer to "do we have a standard for everything", stated as
numbers instead of belief. One row per concern. `Enforcement` is one of:

- `gated`: an executable gate fails a build today.
- `advisory`: a gate exists and reports, but does not block.
- `declared`: a rule exists in prose or a template, with no machine check.
- `none`: no standard. A named gap, not an oversight.

`Adoption` is measured, not asserted: the sample and date are in the header
of the section. A gate adopted by zero repositories is `declared` no matter
how good the script is.

A `Standard` or `Gate` in another canon repo is written `ext:<repo>/<path>`.
It is verified when the sibling checkout is present and listed as unverified
when it is not, because a single-repo CI clone cannot see it. Unverified is
printed, never silently passed.

The enforcement rows (gated + advisory + declared + none) sum to the
concern count. "With a machine check" does not: a rule can have a working
script that is not wired into a workflow yet, which is exactly the
`declared` state, and counting it as covered without saying so is the
assertion this index exists to prevent.

## How the numbers move

Adding a standard: append the row with enforcement `none` first, then write
the document, then the gate, then flip the row to `advisory`, then
`gated`. Raising adoption is a separate, measurable migration. The totals
table is recomputed when rows change, and
`scripts/check-standards-index.py` fails if a cited file disappears.
